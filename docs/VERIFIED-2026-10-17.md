# Audyt fizycznego laptopa — 2026-10-17

Środowisko: Dell XPS 15 7590, Fedora 43 KDE/Wayland, kernel 7.1.12-100.fc43.x86_64, BIOS 1.42.0. Testy diagnostyczne nie zmieniały konfiguracji systemu. Po zgłoszeniu opóźnienia logowania zastosowano osobną poprawkę timeoutu SDDM, opisaną w FINGERPRINT.md; nie wykonywano ponownego uruchomienia.

## Potwierdzone

- `lspci -nnk`: sterowniki i915, nvidia, iwlwifi, snd_hda_intel, rtsx_pci, thunderbolt, nvme są przypisane.
- `glxinfo -B`: Intel UHD 630, Mesa 25.3.6, `Accelerated: yes`, bezpośrednie renderowanie.
- `nvidia-smi`: GTX 1650, sterownik 580.178.04; API odpowiada.
- PRIME `glxinfo -B`: renderer GTX 1650 i OpenGL 4.6 NVIDIA. Sprawdzono utworzenie kontekstu, bez benchmarku/stress testu.
- NetworkManager: Wi-Fi połączone. iwlwifi załadował `cc-a0-77.ucode`.
- PipeWire/WirePlumber: obecne wyjście i wejście analogowe ALSA oraz kamera V4L2.
- Intel Bluetooth: firmware i DDC załadowane; kontroler włączony.
- Brak jednostek systemowych w stanie failed w chwili sprawdzania.
- fwupd widzi BIOS i kontroler Thunderbolt. Nie wykonano sprawdzenia aktualności w sieci ani aktualizacji firmware.

## Wykryte problemy

| Obserwacja | Co wiadomo | Następny krok |
|---|---|---|
| NVIDIA `NV_ERR_NO_MEMORY`, błędy ACPI D-Notifier | Historyczne wpisy w bieżącym rozruchu; test PRIME i API obecnie przechodzi | Odtworzyć pod obciążeniem, porównać logi i wersje; bez diagnozowania usterki GPU na podstawie samego wpisu |
| Autostart `nvidia-settings` failed | GUI ustawień zakończyło się kodem 1; sterownik renderuje poprawnie | Sprawdzić uruchamianie narzędzia w sesji Wayland |
| Touchpad `Touch jump detected and discarded` | KWin/libinput odrzucał skoki | Przetestować gesty i ruch, porównać na innym kernelu; nie dodano przypadkowych quirków |
| fprintd: odmowy SELinux dla `nr_hugepages` | Własny driver Goodix/SIGFM jest aktywny; log zawiera `verify-no-match` | Sprawdzić etykiety i AVC oraz osobno poprawne/błędne dopasowanie; nie wyłączono SELinux |
| i915 `Failed to probe lspcon` | Akceleracja wewnętrznego ekranu działa | Osobny test HDMI/USB-C |
| FAT na `mmcblk0p1`: invalid cluster chain, read-only | Sterownik czytnika działa, ale system plików zgłasza błędy | Najpierw kopia/odzysk danych; naprawa systemu plików poza zakresem zestawu sterowników |
| DrKonqi user service failed | Problem zbierania raportów awarii użytkownika | Osobna diagnostyka pulpitu; nie dowodzi braku sterownika |

Pierwsze próby w piaskownicy nie miały dostępu do USB, NVIDIA i D-Bus. Wyniki powtórzono poza piaskownicą: NVIDIA, Wi-Fi i PipeWire odpowiadają. Błędu dostępu narzędzia nie należy utożsamiać z awarią urządzenia.

## Jeszcze niezweryfikowane użytkowo

Odsłuch głośników i słuchawek, mikrofon, obraz kamery, parowanie i transmisja Bluetooth, suspend/resume, hibernacja, HDMI/DP, stacja Thunderbolt, transfer USB, poprawny zapis SD, czas pracy baterii, jasność i wszystkie skróty Fn. Lista kroków znajduje się w TESTING.md. Nie można rzetelnie oznaczyć ich jako „wszystko działa” na podstawie wykrycia sterowników.

## Uzupełnienie po zgłoszeniu opóźnienia logowania

Analiza czterech rozruchów potwierdziła 30-sekundowe oczekiwanie SDDM na palec przed hasłem (w jednym dwie próby). W bieżącym rozruchu późniejsza próba zakończyła się `verify-match`; nie jest to jednak przeprowadzony przez nas test biometryczny. Ograniczono próbę w SDDM do 8 s i jednej próby, wykonano kopię oryginału, sprawdzono wynik zapisu i poprawność authselect. Test po zimnym starcie pozostaje do wykonania.
